# welcome.blade.php — Main Blade template that bootstraps the React SPA

## Overview

This is the HTML template that serves every authenticated request to the Lesson Generator web app. It is a minimal Blade file (Laravel's templating language) that includes the CSS and JavaScript bundles for the React app, and provides a placeholder `<div>` where React renders. It also includes a CSRF token in a `<meta>` tag for form security.

## File Location
`resources/views/welcome.blade.php`

## What It Renders

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <meta name="csrf-token" content="[CSRF TOKEN]">
    <title>Lesson Generator</title>
    <!-- Vite CSS and JS -->
  </head>
  <body>
    <div id="app"></div>  <!-- React renders here -->
  </body>
</html>
```

## Key Elements

### `<meta name="csrf-token">`

```html
<meta name="csrf-token" content="{{ csrf_token() }}">
```

**What it does:** Generates a CSRF (Cross-Site Request Forgery) token and embeds it in a `<meta>` tag so JavaScript can read it.

**Why it's needed:**
- Laravel protects against CSRF attacks by requiring a token to be submitted with any form that modifies state (POST, PUT, DELETE)
- The token is unique per session and verified by the server
- Forms need to include the token in a hidden input field (e.g. the logout form in `Layout.jsx`)
- React components can read the token from this `<meta>` tag and include it in fetch/axios requests

**How it's used in the app:**
- The logout form in `Layout.jsx` reads this token:
  ```jsx
  const token = document.querySelector('meta[name="csrf-token"]')?.content;
  ```
- The logout form includes it as a hidden input:
  ```jsx
  <input type="hidden" name="_token" value={token} />
  ```
- When the form is submitted, Laravel's CSRF middleware verifies the token matches the session's stored token

**Token generation:** `{{ csrf_token() }}` is a Blade helper that generates a new token (or retrieves the existing one for this session) and returns it as a string.

### `@viteReactRefresh`

```html
@viteReactRefresh
```

**What it does:** A Blade directive that injects a script for Vite's React Fast Refresh. This enables hot module replacement (HMR) during local development — when you edit a React component, the browser automatically reloads only that component without losing state.

**Important note:** This directive MUST be present in the Blade template for `npm run dev` (the local development server) to work. Without it, React Fast Refresh does not function.

---

### `@vite(['resources/css/app.css', 'resources/js/App.jsx'])`

```html
@vite(['resources/css/app.css', 'resources/js/App.jsx'])
```

**What it does:** A Blade directive that includes the CSS and JavaScript bundles built by Vite.

**Details:**
- `resources/css/app.css` — The main stylesheet (includes Tailwind CSS and any custom styles)
- `resources/js/App.jsx` — The React app entry point; exports the root `<App>` component

**How it works:**
- During `npm run dev` (development), Vite serves these files unbundled (as ES modules), allowing fast builds and hot reloading
- During `npm run build` (production), Vite bundles them into optimized files and hashes them for cache busting
- The `@vite()` directive automatically handles both modes — it outputs the correct script/link tags based on whether the app is in development or production

**Output in development:**
```html
<script type="module" src="http://localhost:5173/@vite/client"></script>
<script type="module" src="http://localhost:5173/resources/js/App.jsx"></script>
<link rel="stylesheet" href="http://localhost:5173/resources/css/app.css">
```

**Output in production:**
```html
<script type="module" src="/build/assets/app-abc123.js"></script>
<link rel="stylesheet" href="/build/assets/app-def456.css">
```

---

### `<div id="app"></div>`

```html
<div id="app"></div>
```

**What it does:** A placeholder `<div>` with the ID `app`.

**How it's used:** React mounts the app here. In `resources/js/app.jsx` (the entry point), the code is something like:

```jsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';

ReactDOM.createRoot(document.getElementById('app')).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

React finds this element and renders the entire `<App>` component tree inside it. This is the only actual HTML content in the page — everything else is generated by React.

### Language and Metadata

```html
<html lang="{{ str_replace('_', '-', app()->getLocale()) }}">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Lesson Generator</title>
```

**What they do:**
- `lang` — Sets the document language (for accessibility; Blade helper converts `en_US` to `en-US`)
- `charset` — Declares the character encoding as UTF-8 (supports international text)
- `viewport` — Makes the page responsive on mobile devices (tells the browser to use the device's actual width, not assume a desktop width)
- `title` — The page title shown in the browser tab

## How It Fits Into the App

The request flow is:

1. **Teacher loads any authenticated page** (e.g. visits `/generate`)
   ```
   GET /generate
   → Laravel routing: matches the /{any} catch-all route (from web.php)
   → Teacher is authenticated, so the route is allowed
   → Laravel executes: return view('welcome');
   ```

2. **Laravel renders this Blade template:**
   ```
   → Blade processes @viteReactRefresh and @vite() directives
   → CSRF token is generated and embedded in <meta name="csrf-token">
   → HTML is returned to the browser
   ```

3. **Browser receives HTML and loads Vite bundles:**
   ```
   <script src="http://localhost:5173/resources/js/App.jsx"></script>
   <link href="http://localhost:5173/resources/css/app.css">
   → Vite loads React and the app code
   ```

4. **React mounts and renders:**
   ```
   → React finds <div id="app"></div>
   → React Router parses the current URL (/generate)
   → React Router renders the appropriate page component (GeneratePage)
   → Teacher sees the activity generation form
   ```

5. **Teacher interacts with the app:**
   ```
   → Clicks upload button → API call to POST /api/documents
   → Clicks generate button → API call to POST /api/generate
   → Clicks logout → Form submission (with CSRF token) to POST /logout
   → All these requests send the session cookie automatically
   ```

### Why This Approach?

This is the standard architecture for server-rendered SPA frameworks:

- **Blade template** (`welcome.blade.php`) — Rendered by the server on each page load, includes the HTML shell and security tokens
- **React SPA** (`App.jsx`) — Handles all UI rendering and navigation once loaded
- **API routes** (`api.php`) — Provide JSON data to the frontend (documents, activities, generated content)
- **Web routes** (`web.php`) — Serve the Blade template for all authenticated URLs (catch-all pattern)

The advantage is that:
- The server can verify authentication before serving the template (no unauthenticated users see the SPA)
- The CSRF token is secure (generated server-side, stored in the session)
- The app is fast (React Router handles navigation without page reloads)
- API calls are protected by session middleware and CSRF validation

### Key Security Elements

1. **CSRF Token in `<meta>` tag** — Protects forms (like logout) from cross-site attacks
2. **Session authentication** — Only authenticated teachers see the SPA; unauthenticated users are redirected to `/login`
3. **API middleware** — All API routes require `auth:web` middleware, so only logged-in teachers can make API calls
4. **Session regeneration** — After login, the session ID is regenerated to prevent session fixation attacks
