# DialogGapFillActivity — Dialog with fill-in-the-blank sentences

## Overview
This component displays a conversation (dialog) between two speakers where exactly 3 lines are blanked out. For each blank line, the student must choose the correct option from 3 multiple-choice options. The component renders the conversation as a chat-like interface with colored bubbles (one color per speaker), shows which blanks are answered correctly or incorrectly, keeps a running score, and supports fullscreen presentation mode and keyboard shortcuts.

The component is displayed fullscreen, optimized for sharing during live lessons. A single background image covers the entire dialog (unlike Quiz, which changes background per question).

## File Location
`resources/js/components/DialogGapFillActivity.jsx`

## Props
| Prop | Type | Required | Description |
|------|------|----------|-------------|
| activity | object | Yes | The activity object generated by Claude, containing the full dialog structure with blanks and options (see JSON schema below) |
| onClose | function | Yes | Callback function invoked when the user clicks the Close button to exit the activity |

## State

- **currentBlank** — The index (starting at 0) into the `blanks` array tracking which of the 3 blanks the student is currently answering. Used to highlight the active blank line and determine which options to show.
- **answers** — Object mapping dialog line index to `{ chosen: optionIndex, correct: true/false }`. Tracks every blank the student has answered, storing both the option they selected and whether it was right.
- **selected** — The index of the option the student clicked for the current blank (0, 1, or 2); `null` if they have not answered yet. Used to highlight the selected option and show correct/wrong feedback.
- **finished** — Boolean; `true` when the student has answered all 3 blanks and clicked "See Results". Shows the final score screen instead of the dialog.
- **bgUrl** — URL string of the background image fetched from Unsplash (or Picsum fallback). `null` while loading.
- **showSave** — Boolean; `true` when the user clicks the Save button, which overlays the SavePanel component.
- **isFullscreen** — Boolean from `useFullscreen` hook; `true` when the browser is in fullscreen mode.

## Key Hooks Used

- **useState** — Manages all state (blanks, answers, selection, finished status, background URL, save panel visibility)
- **useEffect** (line 25–29) — Fetches the background image from `/api/background` using the `keyword` or `topic` field from the activity. Runs once on mount.
- **useEffect** (line 31–33) — Scrolls to the currently active blank line smoothly when `currentBlank` changes, ensuring the user always sees the active question.
- **useEffect** (line 35–42) — Registers keyboard event listeners:
  - Space key: If an answer is selected, advances to the next blank
  - F key: Toggles fullscreen mode
- **useFullscreen** — Custom hook that manages browser fullscreen API and provides `isFullscreen` boolean and `toggle()` function
- **useRef** (line 18) — `dialogEndRef` is attached to a div at the end of the dialog list; used for scroll-to-bottom behavior

## User Interactions

### Choosing an Answer
- Student clicks one of the 3 option buttons under "What does [speaker] say?"
- `handleChoose()` is called:
  - Checks if an answer was already selected (if so, returns early to prevent re-answering)
  - Records the option index and whether it was correct in the `answers` object
  - Sets `selected` to the clicked option index
- Immediately, the option buttons change appearance:
  - Correct option turns green
  - Chosen wrong option turns red
  - Other options fade to white/10 (disabled look)

### Advancing to Next Blank
- After choosing, a "Next →" button appears (or "See Results" on the last blank)
- Student clicks Next, or presses Space
- `handleNext()` is called:
  - If this was the last blank, sets `finished = true`
  - Otherwise, increments `currentBlank` and resets `selected = null` (to allow the next blank to be answered)

### Fullscreen Toggle
- Student clicks the fullscreen icon (⛶ or ⊡) in the top right, or presses F
- `toggleFullscreen()` is invoked from the `useFullscreen` hook
- Browser enters native fullscreen; the layout stays the same (already `fixed inset-0`)

### Save Activity
- Student clicks "Save" button
- Sets `showSave = true`, overlaying the SavePanel component
- After saving, `onClose` callback sets it back to false

### Close Activity
- Student clicks the × button in the top right
- Invokes `onClose` callback, which typically returns to the home or library screen

## What It Renders

### Layout Structure
The component is a fixed, fullscreen overlay with a dark semi-transparent scrim (`bg-black/65`) behind all content. Three main zones:

1. **Header** (top, dark)
   - Left: Topic name and "Gap X / 3" counter
   - Right: Running score, Save button, Fullscreen toggle, Close button

2. **Dialog Scroll Area** (center, flex-1 to fill space)
   - Each line of the dialog rendered as a chat bubble (left or right depending on speaker)
   - Non-blank lines show the text normally
   - Answered blanks show the answer in green (✓) or red (✗), with the correct answer shown below if wrong
   - Active unanswered blank (yellow ring) shows "Choose below…" in italic, pulsing text

3. **Options + Next Section** (bottom, fixed height)
   - Label "What does [speaker] say?"
   - 3 option buttons; appearance changes based on answering state (described under User Interactions)
   - Next/See Results button (appears only after answering)

### Visual Details
- **Chat bubbles:** 75% max width, rounded corners, different background colors per speaker (blue-600 for right, white/15 for left)
- **Active blank:** Yellow ring (`ring-2 ring-yellow-400/70`) around the bubble
- **Answers:** Green text for correct, red for wrong, with a green subtitle showing the correct line if they chose wrong
- **Background:** Full-screen image from Unsplash; falls back to a dark gradient if loading fails

### Finished Screen
If `finished = true`, the dialog is replaced with a centered overlay showing:
- "Dialog Complete!" heading
- Score: "You got X out of 3"
- Percentage (e.g. "100%")
- Close button

## How It Fits Into the App

**Where used:** This component is rendered by the `GeneratePage` (or `ActivityPage`) when the teacher/student launches a dialog gap-fill activity, either from the Generation screen or from the Activity Library.

**Triggered by:** The `ActivityController::generate()` endpoint is called with `type: 'dialog_gap_fill'`, which calls `ClaudeService::generateDialogGapFill()`. The returned JSON is passed to this component as the `activity` prop.

**Data flow:**
1. Teacher types a prompt (e.g. "Create a hotel check-in dialog with 3 blanks") on the Generate screen
2. Form submits, calling `/api/activities/generate` with the document ID, prompt, and `type: 'dialog_gap_fill'`
3. Laravel controller sends the document text and prompt to Claude via `generateDialogGapFill()`
4. Claude returns structured JSON with a dialog array and 3 marked blanks
5. React component mounts with the activity data and renders the fullscreen dialog
6. Student interacts with blanks, which updates local state
7. On completion, the finished screen shows the score
8. Close button calls `onClose()` to return to the previous screen
9. If saved, the entire `activity` object is persisted to the `activities` database table for later reuse

**Keyboard shortcuts:**
- Space: advances to next blank (after answering)
- F: toggles fullscreen
- These are the same as Quiz and Unjumble for consistency

**SavePanel integration:** The SavePanel component is passed the full `activity` object and saves it to `/api/activities` with a name and tags.

## JSON Schema (from Claude)

```json
{
  "type": "dialog_gap_fill",
  "topic": "hotel check-in",
  "keyword": "hotel lobby",
  "dialog": [
    {
      "speaker": "Receptionist",
      "line": "Good evening!",
      "blank": false
    },
    {
      "speaker": "Guest",
      "line": "Yes, I have a reservation.",
      "blank": true,
      "options": [
        { "text": "Yes, I have a reservation.", "correct": true },
        { "text": "No, I walked in.", "correct": false },
        { "text": "Can I see the menu?", "correct": false }
      ]
    }
  ]
}
```

The `dialog` array contains 8–14 lines. Exactly 3 lines have `"blank": true`; those lines also have an `options` array with exactly 3 options (one `"correct": true`, two `"correct": false`).
